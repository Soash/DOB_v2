DawnDock

Version 1.0.1

Molecular docking and virtual screening, without the command line. Five docking engines behind one window — GNINA, Smina, AutoDock Vina, AutoDock 4 and LeDock — with poses scored by a neural network trained on solved crystal structures, not only by a classical scoring function. Receptor and ligand preparation, pocket finding, batch screening, interaction analysis and publication figures are all part of it.

DawnDock

Why we built it

Docking is routine work, but the tooling is not. The engines are Linux command-line programs, the preparation steps are scattered across half a dozen utilities, and the answer arrives as a text file. That is a day of setup before a student runs anything.

One window, in work order

Receptor, ligands, binding site, dock, results, analysis — the six steps run down the side and tick off as you go, so it is always clear what is still missing.

Nothing to set up

Two engines are bundled and work the moment you install. No Python, no compiler, no toolkit, and no administrator password.

Dock fast, then rescore

Dock with a fast classical engine, then rescore the promising poses with the neural network — about nine seconds for five poses, and both sets of numbers stay on screen.

Your files stay with you

Docking runs on your machine and your structures are never uploaded. The network is used only to fetch a PDB you asked for, to add an optional engine, or to check for an update.

It shows its working

Every run writes its config and the exact command line beside the results, so the same calculation can be repeated outside DawnDock, or by a reviewer.

Citable

The release is archived with a DOI, so a paper can point at the exact version its results came from, and the citation is inside the program.
